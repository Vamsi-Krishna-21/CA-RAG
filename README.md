# CA-RAG: Context-Aware Retrieval-Augmented Generation

**Context-Aware Retrieval-Augmented Generation Using Similarity Validation to Handle Context Inconsistencies in Large Language Models**

CA-RAG is a document question-answering system designed to improve the relevance and reliability of answers generated by Large Language Models (LLMs). It retrieves relevant information from uploaded documents and applies similarity validation to help identify context inconsistencies and reduce unsupported answers.

## Features

- **Multiple RAG Modes:** Traditional RAG, CA-RAG, and Enhance CA-RAG.
- **PDF and Document Ingestion:** Extracts document content and divides it into manageable chunks.
- **Adaptive Chunking:** Creates chunks based on document content and configurable chunking settings.
- **Semantic Retrieval:** Uses Sentence Transformers embeddings and FAISS similarity search.
- **Similarity Validation:** Evaluates retrieved evidence for relevance and consistency with the query.
- **Query Rewriting:** Rewrites queries to improve retrieval coverage.
- **Evidence-Based Answer Generation:** Generates answers using retrieved document context.
- **Source Citations:** Provides references to supporting document content.
- **Confidence Scoring:** Estimates answer confidence using the project's validation and evidence mechanisms.
- **Hallucination Detection:** Helps identify answers that lack adequate supporting evidence.
- **Feedback-Based Ranking:** Uses feedback to influence retrieval ranking.
- **Streaming Chat:** Streams generated answers to the frontend.
- **Conversation Management:** Supports persistent conversations and chat history.
- **User Authentication:** Provides authentication using JWT and password hashing.
- **Persistent Chunk Storage:** Stores document chunks and serialized embeddings in MongoDB Atlas.
- **FAISS Index Reconstruction:** Rebuilds local retrieval indexes from stored chunk data when required.

## RAG Modes

### 1. Traditional RAG

Traditional Retrieval-Augmented Generation retrieves relevant document chunks and uses them as context for answer generation.

### 2. CA-RAG

CA-RAG introduces similarity validation into the retrieval and answer-selection workflow to help identify context inconsistencies and improve evidence relevance.

### 3. Enhance CA-RAG

Enhance CA-RAG provides the project's enhanced retrieval and answer-selection workflow. Its behavior depends on the implemented validation, evidence-selection, and confidence mechanisms.

## Prerequisites

Install the following before running the project:

- Python 3.12
- Node.js and npm
- MongoDB Atlas account or a compatible MongoDB deployment
- Ollama
- Git

## Local Setup

### 1. Clone the repository

```bash
git clone https://github.com/Vamsi-Krishna-21/ca-rag1.git
cd ca-rag1
```

### 2. Configure the backend

```bash
cd backend
python -m venv venv
```

Activate the virtual environment on Windows CMD:

```cmd
venv\Scripts\activate
```

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

### 3. Configure environment variables

Create or update `backend/.env` with the configuration required by your backend.

Example for local Ollama usage:

```env
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=llama3.1

MONGODB_URI=your_mongodb_connection_string
MONGODB_DB=your_database_name

JWT_SECRET=your_secure_random_secret
FRONTEND_URL=http://localhost:5173
CORS_ORIGINS=http://localhost:5173

EMBEDDING_MODEL=all-MiniLM-L6-v2
```

Use the exact additional environment variables required by your current `backend/app/config.py`.

**Security:** Replace example values with your own configuration. Never commit `.env` files, database credentials, JWT secrets, or API keys to GitHub.

### 4. Start Ollama

Install Ollama from [ollama.com](https://ollama.com/) if necessary, then download the model:

```bash
ollama pull llama3.1
```

Start the model:

```bash
ollama run llama3.1
```

Ensure Ollama is accessible at `http://127.0.0.1:11434`.

### 5. Start the backend

From the `backend` directory:

```bash
python -m uvicorn app.main:app --reload
```

Backend URL:

```text
http://127.0.0.1:8000
```

FastAPI documentation:

```text
http://127.0.0.1:8000/docs
```

### 6. Start the frontend

Open a second terminal:

```bash
cd frontend
npm install
```

For local development, the Vite configuration should proxy `/api` requests to the backend at `http://localhost:8000`.

Start the frontend:

```bash
npm run dev
```

Open the local URL printed by Vite, usually:

```text
http://localhost:5173
```

If you configure `VITE_API_URL`, use the backend base URL expected by `frontend/src/services/apiConfig.js`. The helper normalizes the `/api` prefix.

## Document Persistence

CA-RAG stores document chunks and their embeddings in a MongoDB Atlas `chunks` collection. Embeddings are serialized as BSON binary data to preserve their `float32` representation.

The backend can reconstruct the FAISS index and associated chunk metadata from MongoDB when the local index files are unavailable.

This supports recovery from ephemeral local-storage loss for documents whose chunk data has already been persisted.

**Important limitations:**

- The original uploaded document files may still reside on local disk. Persistent chunk storage does not guarantee persistence of the original files.
- Documents ingested before chunk persistence was implemented may need to be uploaded again if their local data is unavailable.
- MongoDB Atlas storage and resource limits still apply.
- The LLM provider and embedding model must be configured and accessible for the corresponding functionality to work.

## Deployment Notes

- **Frontend:** Vercel or another compatible static frontend host.
- **Backend:** A Python-compatible host that supports FastAPI, the required dependencies, and the backend's memory requirements.
- **Database:** MongoDB Atlas.
- **LLM:** Ollama for local development or a supported hosted API provider when correctly configured.

Free hosting plans can impose memory limits, sleep during inactivity, or restrict persistent storage. Verify current provider limits before deployment.

For cloud deployments, configure the backend URL through the frontend's `VITE_API_URL` environment variable and configure the backend's database, authentication, CORS, and LLM environment variables separately.
